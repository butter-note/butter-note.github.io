# 구축 사례·FAQ 운영

## 연결 대상

- 구축 사례: 「노션 구축 사례 관리」, DB ID `53c6f0cc-b4bd-836c-b7ba-81ce9dcf9112`
- FAQ: 「노션 FAQ 관리」, DB ID `6f66f0cc-b4bd-8283-b9f1-81cfb443f798`
- 설정 파일: `config/notion-business.json`. 링크의 `v=` 값은 보기 ID이므로 사용하지 않는다.
- 실제 DB 속성 및 Integration 권한은 아직 확인되지 않았다. 첫 실제 동기화 전에 아래 공개 기준과 일치하는지 확인한다.

두 **원본 데이터베이스**에서 기존 홈페이지 Integration을 연결하고 콘텐츠 읽기 권한을 허용한다. 별도 공개 웹 게시 또는 API 키의 브라우저 노출은 필요하지 않다.

DB에 데이터 소스가 하나면 자동으로 ID를 찾는다. 여러 개라면 선택하지 않고 동기화를 중단한다. 이때 GitHub Actions에 `NOTION_CASES_DATA_SOURCE_ID`, `NOTION_FAQ_DATA_SOURCE_ID`를 각각 지정한다. API 키는 기존 `NOTION_API_KEY` Secret만 사용한다.

## 노션 속성

| 속성 | 형식 | 용도 |
| --- | --- | --- |
| 제목/질문/이름 | 제목 | 필수. 이름과 관계없이 제목 유형의 속성을 사용 |
| 공개 | 체크박스 | 공개할 항목만 체크. 또는 아래 상태 속성 사용 |
| 상태 | 상태 또는 선택 | `발행`, `공개`, `게시`, `Published`일 때만 공개 |
| 카테고리 | 선택 또는 상태 | 목록 필터. 없으면 사례는 ‘구축 사례’, FAQ는 ‘일반’ |
| 요약 | 텍스트 | 사례 카드 설명, 검색, 공유 설명 |
| 정렬 | 숫자 | 작은 숫자 우선. 비어 있으면 9999 |
| Slug | 텍스트 | 선택 사항. 비어 있으면 페이지 ID 사용. 사례 주소는 발행 후 유지 권장 |
| 업종 | 선택 | 사례에만 표시. 없으면 숨김 |
| 발행일 | 날짜 | 사례 정렬 및 상세 정보. 없으면 숨김 |
| 답변 | 텍스트 | FAQ 페이지 본문이 비었을 때만 사용 |

`공개`와 `상태`가 **둘 다 있으면 둘 다 공개 조건을 만족해야 한다**. 공개 속성이 없거나 잘못된 유형이면 동기화를 중단한다. 초안, 보관, 휴지통 항목은 게시하지 않는다. 권한 오류를 공개 항목 0개로 처리하지 않는다.

지원 별칭: 공개(`홈페이지 공개`, `웹 공개`, `게시`, `발행 상태`, `공개 상태`, `Published`, `Publish`, `Status`), 분류(`분류`, `Category`), 요약(`설명`, `Description`), 정렬(`순서`, `노출 순서`, `Order`), Slug(`슬러그`), 업종(`Industry`), 발행일(`공개일`, `Date`), 답변(`Answer`). 별칭은 대소문자와 공백을 무시한다. 인식하지 못한 공개 속성 이름을 임의로 추측하지 않는다.

## 본문 작성과 공개 범위

구축 사례는 노션 페이지 본문을 작성한다. FAQ는 제목 속성에 질문, 페이지 본문에 답변을 작성하는 방식을 권장한다. 본문이 없을 때만 ‘답변’ 텍스트 속성을 사용한다. 본문에는 기존 노션 블로그와 같은 제목·목록·표·콜아웃·이미지 등의 변환 및 보안 필터를 적용한다. 스타일을 따로 만들지 않는다.

연락처, 내부 메모, 고객 정보 등 DB의 나머지 속성은 내보내지 않는다. **다만 공개 페이지 본문과 첨부 이미지에 들어 있는 정보는 공개된다.** 고객 동의 없는 이름·화면·연락처·매출 자료를 본문에 넣지 않는다. 임의의 성공 사례나 성과 수치는 사이트에서 생성하지 않는다.

제목이나 본문이 없거나, 중복 Slug, 잘린 본문, 접근할 수 없는 블록이 있으면 동기화를 중단한다. 이미지 만료 시에는 기존 블로그와 동일하게 안내 문구와 원본 링크를 표시한다. 실제 데이터 소스 전체를 페이지네이션으로 조회하며, 노션의 특정 보기 필터에는 의존하지 않는다.

## 동기화와 확인

1. 노션에서 작성하고 공개 조건을 설정한다.
2. 기존 GitHub Pages 배포 작업에서 `npm run sync:notion:business`가 두 DB를 조회한다.
3. 두 조회가 모두 끝난 후 `content/business/content.json` 스냅샷을 교체한다. 실패 시 이전 스냅샷을 유지하고 배포를 중단한다.
4. 정적 빌드에서 본문 변환을 검증한 뒤 배포한다. 기존 약 10분 간격 예약에 포함되며, GitHub 실행 대기에 따라 더 늦어질 수 있다.
5. `/cases/`, 사례 상세 주소, `/faq/`에서 확인한다. 공개 해제·삭제도 다음 성공한 배포에서 반영된다.

로컬에서는 안전하게 설정한 환경 변수 또는 무시되는 `.env.local`을 사용한다. `.env.local` 사용 시 `node --env-file=.env.local scripts/sync-notion-business.mjs`로 실행한다. `npm run sync:notion:business`는 운영체제 환경 변수를 읽는다. 키를 문서나 코드에 넣지 않는다.

API 키가 없으면 로컬에서 실제 조회할 수 없다. 기본 스냅샷은 빈 목록이며 샘플 고객 사례를 표시하지 않는다. 새 코드가 배포되기 전에는 운영 사이트에 변경되지 않는다.

## 화면 패턴

- 블로그 내부 메뉴: 일반 링크 기반 `BlogNav`, 현재 항목에 `aria-current="page"`. 키보드 Tab으로 이동. 기존 상단 메뉴 폭 유지.
- 사례 목록: `CatalogBrowser`와 기존 브랜드 색상·폰트·테두리 재사용. 6개씩, 데스크톱 3열→태블릿 2열→모바일 1열.
- FAQ: 8개씩, 질문·답변·분류 검색. 기본 `details/summary`로 클릭, Enter, Space 열기/닫기. 여러 질문을 동시에 열 수 있다. JavaScript 없이도 답변 열람 가능.
- FAQ 안의 제목·목차 앵커는 질문 ID별로 분리한다. 긴 표는 기존 가로 스크롤 패턴을 사용한다.
- 빈 목록과 검색 결과 없음은 별도 문구로 표시한다. 하단에는 이메일 문의를 제공한다.
